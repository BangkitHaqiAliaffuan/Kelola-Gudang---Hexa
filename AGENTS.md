# Kelola Gudang Pro

WMS monorepo — **no root manifest** (ignore stray `package-lock.json` at root). Git at root (`main`); commit from root, not inside `Frontend/`/`Backend/`. Lovable-connected → never force-push / rewrite published history. Two siblings: `Frontend/` (TanStack Start + React 19, Indonesian UI) and `Backend/` (Laravel 13 API). Read `Frontend/AGENTS.md` / `Backend/AGENTS.md` before touching that sub-project — authoritative for stack details. Linux setup: `Frontend/docs/catatan-linux-min.md`.

## Running (two servers required)

- Backend `composer dev` in `Backend/` → `http://127.0.0.1:8000` (serve+queue+pail+vite). Frontend `npm run dev` in `Frontend/` → `http://localhost:8080` (8080 injected by `@lovable.dev/vite-tanstack-config`, not 8081). Vite proxies `/api` + `/sanctum` → `8000` (`Frontend/vite.config.ts`); "Tidak dapat terhubung ke server backend" means Laravel is down.
- Wrapper `./dev.sh` at root — bash native on Linux, **Git Bash/MSYS on Windows, not PowerShell**. Checks ports 8000/8080, logs to `.dev/logs/`, kills on Ctrl+C. Runs plain `php artisan serve` (no queue/pail; `composer dev` is the full loop). Skip ngrok: `SKIP_TUNNEL=1 ./dev.sh`.
- Prod is same-origin: `VITE_API_URL` stays **unset** (fallback `/api` in `Frontend/src/lib/api.ts`). `Frontend/vercel.json` rewrites `/api/*` + `/sanctum/*` → ngrok URL. `dev.sh` auto-injects the current ngrok URL into `vercel.json` (rotates each restart → commit + redeploy Vercel); never hand-edit the destination. Do not set `VITE_API_URL` on Vercel. `Backend/config/cors.php` (`allowed_origins` from `FRONTEND_URL`, `supports_credentials:false`) only matters for rare direct cross-origin calls.
- DB: **PostgreSQL 16** at `127.0.0.1:5432` (`postgres`/`postgres`). Dev DB `kelolagudang`, test DB `kelolagudang_test` (`Backend/phpunit.xml`). First-time: `CREATE DATABASE kelolagudang; CREATE DATABASE kelolagudang_test;` with the native client (`psql`/`pg_isready` on Linux).

- Commands in `Frontend/`: `npm run dev` (regenerates `routeTree.gen.ts`), `npm run build` / `build:dev` / `preview`, `npm run lint` (`eslint .`, `@typescript-eslint/no-unused-vars` OFF), `npm run format`, `npm test` (`vitest run` — 5 specs, 52 tests: `index`, `wms-data`, `barcode-label`, `stock-document-search`, `use-warehouse-filter`), `npx tsc --noEmit` (no typecheck script). Rest is deterministic dummy `src/lib/wms-data.ts` (seeded PRNG); persediaan/transaksi hooks in `src/hooks/use-persediaan.ts`, types in `src/lib/persediaan-types.ts`.

## Backend

- Stack PHP 8.3, Laravel 13. Commands in `Backend/`: `composer dev` (serve+queue+pail+vite), `composer test` (= `php artisan test`, PHPUnit 12, `RefreshDatabase` wipes `kelolagudang_test`), `php artisan test --filter=Name` / `vendor/bin/phpunit tests/Feature/FooTest.php`, `vendor/bin/pint`, `php artisan migrate` (never `migrate:fresh` — see below).
- API `routes/api.php` (`bootstrap/app.php` `withRouting(api:…)`). Auth Sanctum **bearer-token** only (`POST /api/auth/login` throttle 5/min → `{data,access,token}`, `GET /api/auth/me`, `POST /api/auth/logout`); token in `localStorage` `kg-token` (`src/lib/api.ts`) as `Authorization: Bearer`. No `statefulApi()`, no cookies/CSRF.
- RBAC via `role.access` (`EnsureRoleAccess`), level from verb (GET=Baca, POST/PUT/PATCH=Tulis, DELETE=Kelola); missing `(role,module)` row = no access. `/api/master/*` → `Master Data`, `/api/persediaan/*` → `Persediaan`, `/api/pengadaan/*` → `Pengadaan`, `/api/laporan/*` → `Laporan` (`role_permissions` seeded by `RolePermissionSeeder`). **Approve/unlock actions sit under plain `auth:sanctum`** (assignee-only, no module gate): persediaan `approve`/`reject`/`approve-review`/`reject-review`/`force-unlock`, pengadaan `proc-docs/{id}/approve`/`reject`.
- Envelope `{data}` / `{data,links,meta}`; validation in `FormRequests`; resources map `min_stock→min` etc. + raw FKs + string relation names for form prefill. `items` extras beyond `apiResource`: `bulk-delete`, `bulk-status`, `bulk-import`. `stock-documents` full lifecycle: CRUD + `summary` + `post`/`cancel`/`submit-approval`/`submit-review`/`lock`/`heartbeat`/`unlock`; `pengadaan/proc-docs`: CRUD + `submit`/`cancel`/`reassign`.
- Stock ledger: `items.stock`/`reserved` denormalized; source of truth `item_stock` (PK `item_id,warehouse_id,bin_id`) + `stock_movements`/`stock_documents`+lines via `StockLedger`/`StockDocumentService`. Opname posts 0 movements — completing it creates an `ADJ` **Draft** (draft-then-post from `persediaan/adjustment`). Transfer writes an OUT+IN mirror pair (`pair_id`). See `Backend/AGENTS.md` for schema.

### Never run `migrate:fresh` — SANGAT PENTING
`migrate:fresh` / `migrate:fresh --seed` / any DB-wiping command on dev DB `kelolagudang` is **FORBIDDEN** without explicit user instruction. Wipes users/master/stock/`role_permissions` and breaks login ("Kredensial tidak cocok"). Use new migration + `php artisan migrate`. If dev DB empty, `php artisan db:seed` (every seeder has an `exists()` guard — re-run is a safe no-op; `DatabaseSeeder` runs in one transaction, so an aborted run rolls back instead of leaving partial data). `UserSeeder` requires `DEMO_PASSWORD` from `Backend/.env` (exception if empty; never commit literal passwords — see `Frontend/docs/akun-login.md` + `.env.example`).

## Git rules

- Never `git add`/`commit`/`push`/rewrite history (rebase/merge/amend/force-push) without explicit user instruction. When asked, stage only the files you modified for your task — never `git add .`/`-A`/`git commit -a`, never stage/commit seluruh perubahan walau dari sesi lain. Even with explicit `commit`/`push` permission, only `git add <explicit-path>` for your task; **DILARANG** commit seluruh working tree termasuk file milik sesi lain kecuali user eksplisit tulis `commit all` / sebutkan path. Always filter `git status`: exclude untracked/modified owned by other sessions (see Multi-session protocol #2).
- **`implementasikan`/`lanjutkan`/`fix`/`crosscheck`/`plan` ≠ izin commit/push.** Those mean edit files + verify (`npx tsc --noEmit` / `npm test` / `php artisan test`); `git add`/`commit`/`push` ONLY when user writes `commit`/`push`/`git commit`. Otherwise stop at `git status`/`git diff`. Even when permitted, do NOT include unrelated changes from other sessions — stage only your task's files.
- Before commit: `git status` + `git diff`/`--cached` line-by-line; verify `git diff --cached` contains only your intended files — if foreign changes staged, unstage (`git restore --staged <path>`) and report; scan for secrets (`authtoken`,`api[_-]?key`,`secret`,`password`,`token`,`APP_KEY`, AWS creds, `BEGIN .* PRIVATE KEY`, URL creds); reject `.env*`,`*.key`/`*.pem`/`*.p12`,`ngrok.yml`,`.dev/` artifacts, build output (`dist`,`.output`,`.nitro`,`public/build`),`node_modules`, IDE/OS files. Ensure `.gitignore` covers them. Keep `bun.lock`+`package-lock.json` in sync. If suspicious, stop and report.

## Multi-session protocol

Multiple opencode sessions share one working tree / `main` / test DB / ports 8000+8080 — last-writer-wins.
1. Claim before editing: add `| <path> | <role> | claimed |` to `.dev/claims.md` (gitignored, create on demand); release to `done` when finished. Read it **before every edit**.
2. `git status` is live truth — uncommitted changes you didn't make mean another session owns that file.
3. Serialize edits to same file; never edit a claimed path.
4. Only one session runs `./dev.sh` / `composer test` / `migrate` at a time (ports collide, `RefreshDatabase` wipes `kelolagudang_test`).
5. Small commits per task (only when user asks), short claim windows. On conflict, stop and report.

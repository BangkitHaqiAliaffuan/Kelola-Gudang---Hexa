# Kelola Gudang Pro

WMS monorepo — no root manifest (stray root `package-lock.json` is 99B, ignore it). Git lives at root (`main`); commit from root, never inside `Frontend/`/`Backend/`. Lovable-connected → never force-push / rebase / amend pushed history. Two siblings: `Frontend/` (TanStack Start + React 19, Indonesian UI) and `Backend/` (Laravel 13 API, PHP 8.3+). Read `Frontend/AGENTS.md` / `Backend/AGENTS.md` before touching that side — they are authoritative, this file is only the cross-cutting surface. No CI (no `.github/`), no `opencode.json`/`.opencode/`.

## Running (two servers required)

- Backend in `Backend/`: `php artisan serve` → `http://127.0.0.1:8000` (`composer dev` additionally spins `queue:listen` + `pail` + Backend's own vite via `Backend/package.json` — NOT the Frontend; for API-only work plain `serve` is enough). Frontend in `Frontend/`: `npm run dev` → `http://localhost:8080` (8080 injected by `@lovable.dev/vite-tanstack-config`). Vite proxies `/api` + `/sanctum` → `8000` (`Frontend/vite.config.ts`); "Tidak dapat terhubung ke server backend" means Laravel is down.
- `./dev.sh` (root) = thin wrapper: plain `php artisan serve` + `npm run dev` (no queue/pail). Logs to `.dev/logs/`, kills on Ctrl+C, aborts if 8000/8080 busy. Git Bash/MSYS on Windows, not PowerShell. `SKIP_TUNNEL=1 ./dev.sh` skips ngrok.
- Prod is same-origin: `VITE_API_URL` stays **unset** (fallback `/api` in `Frontend/src/lib/api.ts`). `Frontend/vercel.json` rewrites `/api/*` + `/sanctum/*` → ngrok URL; `dev.sh` `update_vercel_json()` rewrites the destination to the active tunnel URL on every restart (matches any existing ngrok host + previous URL from `.dev/logs/ngrok-url.txt`, so no manual placeholder restore needed) → commit + redeploy Vercel after. Never set `VITE_API_URL` on Vercel.
- `vercel.json` security headers (W5): HSTS/X-Frame/nosniff/Referrer statis; **JANGAN tambah `Content-Security-Policy` statis** — CSP dipasang dinamis oleh `src/server.ts` (W5.1: nonce per-request untuk inline hydration script `$tsr` TanStack Start; isi script dinamis per request sehingga hash statis mustahil, dan dua header CSP ditegakkan keduanya). `style-src` tetap `unsafe-inline` (React `style={{}}`) + `fonts.googleapis.com`, `frame-src 'self' blob:`, `connect-src 'self'`.
- DB: **PostgreSQL 16** at `127.0.0.1:5432` (`postgres`/`postgres`). Dev `kelolagudang`, test `kelolagudang_test` (`Backend/phpunit.xml`). First-time: `CREATE DATABASE kelolagudang; CREATE DATABASE kelolagudang_test;`. Benchmark-only `kelolagudang_bench` exists for `ScaleBenchmarkSeeder` — run only explicitly via `--class` against bench/test, never on dev (it aborts via anti-dev gate; never register it in `DatabaseSeeder`).

## Cross-cutting contracts (details in sub-AGENTS.md)

- Auth Sanctum **bearer-token only**: `POST /api/auth/login` (throttle 5/min → `{data,access,token}`), token in `localStorage` `kg-token` as `Authorization: Bearer`. No `statefulApi()`, no cookies/CSRF. `ngrok-skip-browser-warning: true` is already in `src/lib/api.ts`.
- Tokens expire after 24h (`Backend/config/sanctum.php` `expiration => 1440`) — a 401 on a previously working token means re-login, not a bug. Deactivated users (`is_active=false`) get 401 `Akun ini telah dinonaktifkan` via `user.active` on every gated group — re-login won't help, reactivate the user instead (frontend drops the token on 401).
- RBAC via `role.access` (`EnsureRoleAccess`), level from verb (GET/HEAD=Baca, POST/PUT/PATCH=Tulis, DELETE=Kelola); missing `(role,module)` row = no access. All four middleware aliases (`role.access`, `role.administrator`, `scope.warehouse`, `user.active`) are registered in `Backend/bootstrap/app.php` — look there first when debugging 403/401 gates.
- Most gated groups also run `user.active` (inactive user → 401 even with valid token; exception: `/api/system/settings` has no `user.active`). Persediaan/pengadaan/laporan/ai groups additionally run `scope.warehouse`: scoped roles get narrowed reads (`[]` = zero rows fail-closed) and out-of-scope writes rejected at validation/controller, so missing rows for a scoped user are expected.
- Route-gated modules: `Master Data`, `Persediaan`, `Pengadaan`, `Laporan`, `System` (see `Backend/routes/api.php` + `RolePermissionSeeder`) plus `Audit Trails` (`GET /api/system/audit-logs` lives in `routes/audit.php`, loaded via `AppServiceProvider`). `RolePermission::MODULES` also lists `Transaksi`, `Stock Opname`, `Approval Pengadaan`, but no route gate uses them — UX-gating only.
- **Auth-only actions (plain `auth:sanctum` + `user.active`, no module gate — the second `persediaan`/`pengadaan` groups in `routes/api.php`):** persediaan `approve`/`reject`/`approve-review`/`reject-review` (Auditor or Persediaan `Kelola`, plus SoD — requester can't decide own doc); persediaan `force-unlock` (Persediaan `Kelola` or Auditor, controller-checked); pengadaan `proc-docs/{id}/approve`/`reject` (assigned approver only).
- Everything else under `/api/persediaan/*` and `/api/pengadaan/*` goes through the module gate — incl. `submit-approval`/`submit-review`/`lock`/`heartbeat`/`unlock` (need Persediaan Tulis), `proc-docs/submit`/`cancel` (need Pengadaan Tulis), and `reassign` (needs Pengadaan `Kelola`, controller-checked).
- **Administrator-only writes (`role.administrator`, exact `role === 'Administrator'` match — not a module level):** `POST/PUT/DELETE /api/master/users`, `POST/PUT/DELETE /api/master/roles`, and `PUT /api/system/settings` 403 even with `Kelola`. Reads stay under the module gate so non-admin forms (PIC selects, Role page) keep working.
- Throttles (429 under load — not bugs): login 5/min (inline `throttle:5,1`); `bulk` limiter 10/min (covers `bulk-import` + `sync-cost`); `mutasi` (doc `store`) + `laporan` group 60/min; `ai` 10/min. Named limiters live in `AppServiceProvider` and are bypassed under `runningUnitTests`.
- Envelope `{data}` / `{data,links,meta}`; validation in FormRequests; resources expose raw FKs + string relation names for form prefill. Truth for API surface is `Backend/routes/api.php` — incl. extras beyond `apiResource`: `items/lookup`, `items/cost-drift`, `items/sync-cost`, `items/bulk-*`, `stock-documents/summary`, `GET /laporan/mutasi|keluar-analytics|transaksi-analytics|fast-moving`, `GET|PUT /system/settings`. (README's `per_page=10000` is stale — hooks use `fetchAll()`, see below.)
- Stock ledger: `items.stock`/`reserved` are denormalized; truth is `item_stock` + `stock_movements` via `StockLedger`/`StockDocumentService`. Opname posts 0 movements — finishing it creates an `ADJ` **Draft** (post later from `persediaan/adjustment`). Transfer writes an OUT+IN mirror pair (`pair_id`).
- TanStack Query needs `enabled: typeof window !== "undefined"` (SSR shell). Heavy pages (`persediaan/stock`, `persediaan/mutasi`, `master/barang`) use server pagination via `useServerTable()` (`src/hooks/use-server-table.ts`); everything else fetches all via `fetchAll()` (loop `per_page=100`; backend lists `max:100`, aggregate/report endpoints — `valuation`, `laporan/mutasi`, `fast-moving`, `cost-drift` — `max:500`) and paginates client-side.
- Penomoran (`CodeGenerator`) via tabel `document_counters` O(1) + self-heal ke legacy-max bila kandidat dipakai/didahului nomor manual — jangan kembalikan `pluck`+advisory-lock; gap kecil diterima (lihat `roadmap-final-skalabilitas-wms.md` K1).
- AI Assistant (default OFF, `AI_ENABLED=false`): `POST /api/ai/chat` only proposes (writes become `pending` `ai_proposals` rows), `POST /api/ai/execute` runs them through the real route as the same user. POST endpoints need Persediaan `Tulis` (Auditor/Baca-only gets 403), GET endpoints need `Baca`. Details in `Backend/AGENTS.md` — don't document provider config here.

## Verify (per side, run in that side's dir)

- Frontend (`bun` manages deps, but run via npm): `npm run lint`, `npx tsc --noEmit` (no typecheck script), `npm test` (`vitest run`; single spec via `npx vitest run src/path/name.spec.ts[x]`), `npm run format` (prettier, 100-col). Bun `bunfig.toml` has a 24h `minimumReleaseAge` guard — confirm with user before adding exclusions. Keep `bun.lock` + `package-lock.json` in sync.
- Backend: `composer test` (= `config:clear` + `php artisan test` on `kelolagudang_test`; single test via `php artisan test --filter=Name`), `vendor/bin/pint`.

### Never run `migrate:fresh` — SANGAT PENTING
`migrate:fresh` (or any DB-wiping command) on dev DB `kelolagudang` is **FORBIDDEN** without explicit user instruction — wipes users/master/stock/`role_permissions`, breaks login ("Kredensial tidak cocok"). Use a new migration + `php artisan migrate`. If dev DB is empty, `php artisan db:seed` (seeders are idempotent — `exists()` guards / `firstOrCreate` — so re-run is a safe no-op). `UserSeeder` requires `DEMO_PASSWORD` in `Backend/.env` (throws if empty; never commit literal passwords — see `Frontend/docs/akun-login.md` + `Backend/.env.example`).

## Git rules

- Never `git add`/`commit`/`push`/rewrite history (rebase/merge/amend/force-push) without explicit user instruction. When asked, `git add <explicit-path>` only for your task's files — never `git add .`/`-A`/`commit -a`, never sweep in other sessions' changes even with `commit` permission (unless user writes `commit all` or names the path).
- **`implementasikan`/`lanjutkan`/`fix`/`crosscheck`/`plan` ≠ izin commit/push** — those mean edit + verify; stop at `git status`/`git diff` otherwise.
- Before commit: `git status` + line-by-line `git diff`/`--cached`; if foreign changes are staged, `git restore --staged <path>` and report. Scan for secrets (`authtoken`, `api[_-]?key`, `secret`, `password`, `token`, `APP_KEY`, AWS creds, `BEGIN .* PRIVATE KEY`, URL creds). Reject `.env*`, `*.key`/`*.pem`/`*.p12`, `ngrok.yml`, `.dev/` artifacts, scratch/debug one-offs (`Backend/*.php` scripts, `*.json`/`*.txt` dumps, `tmp-*`), build output (`dist`, `.output`, `.nitro`, `public/build`), `node_modules`. Keep `bun.lock`+`package-lock.json` in sync.

## Multi-session protocol

Multiple opencode sessions share one working tree / `main` / test DB / ports 8000+8080 — last-writer-wins.
1. Claim before editing: read `.dev/claims.md` (gitignored, create on demand) **before every edit**, add `| <path> | <role> | claimed |`; release to `done` when finished.
2. `git status` is live truth — uncommitted changes you didn't make belong to another session.
3. Serialize edits to the same file; never touch a `claimed` path.
4. Only one session at a time runs servers (`./dev.sh` / `composer dev` / `php artisan serve` / `npm run dev`), Playwright e2e (`Frontend/`, auto-starts both servers via `webServer`), `composer test`, or `migrate` — `composer dev` and `dev.sh` both bind port 8000, and `RefreshDatabase` wipes `kelolagudang_test`.
5. Small commits per task (only when asked), short claim windows. On conflict, stop and report.

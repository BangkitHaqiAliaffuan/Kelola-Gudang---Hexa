0. CARA MEMAKAI DOKUMEN INI
======================================================================

- Setiap skenario diberi kode  S-xxx  (mis. S-A01, S-B07).
- Setiap skenario mencantumkan:
    Role     : role mana diuji dan ekspektasi (muncul / 403 / tombol hilang)
    Pre-kondisi: data apa harus ada, login sebagai siapa
    Langkah  : urutan klik/input yang harus dilakukan penguji
    Hasil harap: apa yang harus terlihat di UI / DB / API
- Kolom hasil di akhir tiap skenario:  Lulus / Gagal + Catatan
- Tanda  HARAP LIHAT  menandakan assertion utama (wajib dicek).
- Uji per role bergantian (logout lalu login akun lain) untuk
  memverifikasi gating benar-benar berganti, tidak hardcoded.

1. PRASYARAT & AKUN UJI
======================================================================

1.1 Server
  - Backend Laravel API : http://127.0.0.1:8000   (jalankan via  composer dev  di folder Backend/)
  - Frontend Vite       : http://localhost:8080    (jalankan via  npm run dev  di folder Frontend/)
  - Alternatif wrapper  : ./dev.sh dari root repo (Git Bash/MSYS, bukan PowerShell).
    Pastikan port 8000 dan 8080 bebas sebelum start. Log di .dev/logs/.
  - Vite mem-proxy  /api  -> http://127.0.0.1:8000  (vite.config.ts).
    Jika halaman Master menampilkan "Tidak dapat terhubung ke server
    backend", server Laravel belum jalan.

1.2 Database
  - Dev DB: kelolagudang  (PostgreSQL 18 di 127.0.0.1:5432, user postgres/postgres)
  - Test DB: kelolagudang_test (dipakai PHPUnit)
  - Bila DB kosong: jalankan  php artisan db:seed  di folder Backend/
    JANGAN jalankan  migrate:fresh  (menghapus seluruh data dev).

1.3 Password
  - Seluruh akun memakai password yang sama: nilai DEMO_PASSWORD di
    file Backend/.env  (lihat Frontend/docs/akun-login.md).
  - Tidak ada password literal di repo.

  - Logout  POST /api/auth/logout  menghapus token saat ini.

    - Buat PR/PO butuh Tulis

    - Audit Trails -> butuh Audit Trails
    - General Setting, Developer -> butuh System
    - Supervisor & Operator Gudang -> menu System HILANG, guard 403

  403 screen: bila mengakses URL yang modulnya tidak dimiliki role,
  AppShell menampilkan layar 403 (bukan blank/redirect), dengan pesan
  modul yang dibutuhkan.

4. SKENARIO A - AUTH & RBAC
======================================================================

----------------------------------------------------------------------
S-A01  Login sukses & token
----------------------------------------------------------------------
  Role        : semua
  Pre-kondisi : server jalan, DB seeded
  Langkah:
    1. Buka http://localhost:8080  -> HARAP LIHAT redirect ke /login
       bila belum login.
    2. Masukkan email USR-001 dan password DEMO_PASSWORD, klik Masuk.
    3. HARAP LIHAT redirect ke / (dashboard), nama "Rudi Hartono"
       muncul di navbar kanan atas beserta role "Administrator".
    4. Buka DevTools -> Application -> Local Storage -> key kg-token
       HARAP LIHAT token tersimpan (string panjang, bukan kosong).
    5. Refresh halaman (F5) -> HARAP LIHAT tetap login (tidak kembali ke /login).
  Hasil harap: login sukses, token ada, sesi bertahan setelah refresh.
  Per role  : semua 4 role harus bisa login dengan kredensial masing-masing.
  Kolom hasil: Lulus / Gagal + Catatan
  Sumber: Frontend/src/routes/login.tsx, src/hooks/use-auth.tsx, src/lib/api.ts

----------------------------------------------------------------------
S-A02  Login throttling (5/menit)
----------------------------------------------------------------------
  Role        : tidak login
  Langkah:
    1. Logout bila sedang login.
    2. Di /login, masukkan email valid tapi password salah, klik Masuk
       sebanyak 6 kali berturut-turut dalam 1 menit.
    3. HARAP LIHAT setelah percobaan ke-6 muncul pesan throttled
       (429 / "Terlalu banyak percobaan") dan tombol login tertahan.
  Hasil harap: throttling aktif (middleware throttle:5,1 di AuthController@login).
  Kolom hasil: Lulus / Gagal + Catatan

----------------------------------------------------------------------
S-A03  Akun non-aktif ditolak
----------------------------------------------------------------------
  Role        : Administrator
  Pre-kondisi : ada user dengan is_active = false (buat via Master -> User
                lalu toggle non-aktif, atau via seeder).
  Langkah:
    1. Login sebagai Administrator, buka Master -> User, buat user baru
       dengan is_active = false (atau edit user existing menjadi non-aktif).
    2. Logout, coba login dengan email user non-aktif tersebut.
    3. HARAP LIHAT login ditolak (401 / pesan kredensial tidak cocok /
       akun tidak aktif).
  Hasil harap: user non-aktif tidak bisa login (cek is_active di login).
  Kolom hasil: Lulus / Gagal + Catatan

----------------------------------------------------------------------
S-A04  Logout menghapus token
----------------------------------------------------------------------
  Role        : semua
  Langkah:
    1. Login sebagai akun apapun.
    2. Klik avatar di navbar -> Profil -> Logout (atau tombol logout
       di app-shell).
    3. HARAP LIHAT redirect ke /login, token kg-token hilang dari
       localStorage, akses ke / langsung redirect lagi ke /login.
  Kolom hasil: Lulus / Gagal + Catatan

----------------------------------------------------------------------
S-A05  Guard 403 per modul
----------------------------------------------------------------------
  Role        : Auditor vs Operator Gudang vs Supervisor
  Langkah:
    1. Login sebagai USR-004 Dewi Lestari (Auditor - semua Baca, tidak
       punya Approval Pengadaan).
       - Buka /laporan/stock -> HARAP LIHAT halaman laporan tampil (Auditor punya Laporan Baca).
       - Buka /system/audit-trails -> tampil (punya Audit Trails Baca).
       - Coba akses form Tambah Barang Masuk (/transaksi/entri/masuk)
         -> HARAP LIHAT guard 403 atau tombol Simpan disabled (butuh Persediaan Tulis, Auditor hanya Baca).
    2. Login sebagai USR-005 Agus Salim (Operator Gudang - tanpa Laporan, tanpa System).
       - Buka /laporan/stock -> HARAP LIHAT layar 403 (tidak punya Laporan).
       - Buka /system/audit-trails -> 403.
       - Buka /persediaan/stock -> tampil (punya Persediaan Tulis).
       - Buka /transaksi/masuk -> tampil + tombol Buat ada (punya Persediaan Tulis).
    3. Login sebagai USR-002 Siti Aminah (Supervisor).
       - Buka /master/role -> HARAP LIHAT menu terlihat tapi tombol Edit
         mungkin terbatas (butuh Master Data Kelola, Supervisor hanya Baca).
       - Buka /persediaan/stock -> tampil.
  Kolom hasil: Lulus / Gagal + Catatan

----------------------------------------------------------------------
S-A06  Profil menampilkan role & hak akses yang benar (regresi hardcoded)
----------------------------------------------------------------------
  Role        : semua (uji bergantian)
  Langkah:
    1. Login sebagai USR-001 Rudi Hartono, klik avatar navbar -> dialog Profil.
    2. HARAP LIHAT header dialog = nama + role "Administrator", pill Hak Akses
       8 modul semua Kelola (Master Data, Transaksi, Persediaan, Stock Opname,
       Pengadaan, Laporan, System, Audit Trails).
    3. Logout, login sebagai USR-002 Siti Aminah, buka Profil.
       HARAP LIHAT role "Supervisor", 7 pill (Master Baca, Transaksi Tulis,
       Persediaan Tulis, Stock Opname Baca, Pengadaan Tulis, Approval Baca,
       Laporan Baca).
    4. Logout, login sebagai USR-005 Agus Salim, buka Profil.
       HARAP LIHAT role "Operator Gudang", 5 pill (Master Baca, Transaksi Tulis,
       Persediaan Tulis, Stock Opname Tulis, Pengadaan Baca).
    5. Logout, login sebagai USR-004 Dewi Lestari, buka Profil.
       HARAP LIHAT role "Auditor", 8 pill semua Baca.
    6. HARAP LIHAT setiap ganti user, pill berubah (tidak pernah identik
       untuk role berbeda).
  Kolom hasil: Lulus / Gagal + Catatan
  Sumber: src/components/wms/profile-dialog.tsx, useAuth().access

----------------------------------------------------------------------
S-A07  Sidebar & quick actions terfilter per role
----------------------------------------------------------------------
  Role        : per role
  Langkah:
    1. Login sebagai Auditor -> HARAP LIHAT sidebar TIDAK menampilkan
       tombol Buat yang butuh Tulis, dan menu Laporan/System tetap ada

    2. Login sebagai Operator Gudang -> HARAP LIHAT menu Laporan HILANG

5. SKENARIO B - MASTER DATA (16 entitas + bulk + Role edit)
======================================================================

Master Data adalah 16 halaman di bawah /master/*, semuanya API-backed
(Backend/routes/api.php -> /api/master/* dengan auth:sanctum + role.access:Master Data).
Tidak ada dummy fallback.

  Daftar 16:
    1 Kategori              2 Sub Kategori        3 Merk
    4 Satuan                5 Gudang              6 Rak
    7 Bin Location          8 Supplier            9 Customer
   10 Vendor               11 Barang             12 Departemen
   13 Proyek               14 Work Order         15 User
   16 Role (katalog + edit hak akses)

  Flow umum per entitas (kecuali Role & Barang khusus):
    List (search, pagination, sort) -> Tambah -> Edit -> Hapus (dengan guard)

----------------------------------------------------------------------
S-B01  Kategori CRUD + guard hapus
----------------------------------------------------------------------
  Role        : Administrator (Kelola)
  Langkah:
    1. Buka /master/kategori -> HARAP LIHAT tabel kategori tampil
       dari API (paginated, links/meta), bukan data dummy.
    2. Cari di search box -> HARAP LIHAT hasil terfilter (debounce),
       pagination tetap jalan client-side (per_page=500 di hook).
    3. Klik Tambah Kategori -> isi nama unik, simpan.
       HARAP LIHAT toast sukses, baris baru muncul di tabel.
    4. Klik baris -> Edit -> ubah nama, simpan.
       HARAP LIHAT nama ter-update.
    5. Coba buat kategori dengan nama duplikat -> HARAP LIHAT validasi
       422 (nama sudah terpakai).
    6. Hapus kategori yang masih dipakai Sub Kategori/Barang ->
       HARAP LIHAT 422 ditolak (guard cascade).
    7. Hapus kategori kosong -> HARAP LIHAT sukses, baris hilang.
  Per role:
    - Supervisor/Auditor/Operator Gudang (Baca) -> HARAP LIHAT tombol
      Tambah HILANG, tombol Edit/Hapus HILANG. Akses langsung via URL
      form tetap ditolak (UI gate).
  Kolom hasil: Lulus / Gagal + Catatan

----------------------------------------------------------------------
S-B02  Sub Kategori CRUD + relasi Kategori

    5. Coba hapus Kategori yang masih punya Sub Kategori ->

----------------------------------------------------------------------
S-B03  Merk & Satuan CRUD

S-B07  Supplier / Customer / Vendor CRUD (detail PT + validasi NIB/NPWP)

         - NIB selain 13 digit -> 422
         - NPWP tidak Luhn -> 422
         - website tanpa scheme -> ditolak zod
    3. Supplier duplikat NIB/NPWP? -> cek unik (bila backend enforce unique).
    4. Edit -> ubah legal_name, simpan -> HARAP LIHAT ter-update.
    5. Hapus Supplier yang masih jadi preferred_supplier di Barang -> 422.
    6. Ulangi untuk /master/customer (segment Retail/Distributor/Proyek/Korporat)

    8. Detail sheet (klik baris) -> HARAP LIHAT panel party-detail menampilkan

----------------------------------------------------------------------
S-B08  Barang CRUD + auto SKU, barcode, gudang/rak/bin, supplier
----------------------------------------------------------------------
  Role        : Administrator
  Langkah:
    1. Buka /master/barang -> tabel barang (sku, nama, kategori, stok, harga).
    2. Klik Tambah Barang ->
       HARAP LIHAT field SKU (Kode) sudah terisi otomatis "SKU-xxxxx-001"
       dengan hint "Diisi otomatis dengan SKU berikutnya - bisa diubah."
    3. Ganti SKU dengan nilai unik lain (mis. SKU-99000-001), lengkapi:
       - Kategori (wajib), Sub Kategori (opsional), Merk, Satuan,
       - Gudang Default, Rak Default, Bin Default (berjenjang, filter per gudang),
       - Preferred Supplier,
       - min_stock, max_stock, lead_time, cost (harga),
       - barcode / internal_barcode,

       HARAP LIHAT barang tersimpan dengan SKU ubahan.
    4. Tambah Barang lagi -> HARAP LIHAT SKU auto-suggest sudah naik
       (tidak mengulang nilai sebelumnya).
    5. Coba SKU duplikat -> HARAP LIHAT 422 unique.
    6. Edit barang existing -> HARAP LIHAT SKU menampilkan nilai lama,
       hint auto tidak muncul, tidak diganti otomatis.
    7. Barcodes: HARAP LIHAT internal_barcode auto-generate bila kosong.

      "Sesi tidak ditemukan".
    - Navigasi ke /persediaan/adjustment/new langsung via URL (butuh Tulis)
      -> Auditor (Baca) -> HARAP LIHAT tombol tidak ada atau guard.

L-03  Langkah cepat (setup & data uji)
----------------------------------------------------------------------
  - Mulai server: ./dev.sh dari root (Git Bash/MSYS). Log: .dev/logs/.
    Atau manual: composer dev (Backend) + npm run dev (Frontend).
  - Login: buka localhost:8080, masukkan email + DEMO_PASSWORD dari Backend/.env.
  - Buat BM uji: Transaksi -> Barang Masuk -> Buat (butuh Persediaan Tulis).
  - Buat BK uji: Transaksi -> Barang Keluar -> Buat.
  - Buat sesi opname uji: Opname -> Jadwal -> Buat Jadwal (pilih gudang berisi stok)
    -> Opname -> Proses -> klik sesi.
  - Siapkan PO Disetujui: Pengadaan -> Purchase Order -> Buat dari PR Disetujui
    atau approval PR/PO.
  - Siapkan retur: pastikan ada BM Selesai (untuk RP) dan BK Selesai (untuk RJ)
    di gudang yang sama.
  - Reset hak akses: Master -> Role -> Edit -> kembalikan ke defaults
    (lihat Bagian 2) setelah uji manipulasi role.
